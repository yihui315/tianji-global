## Corrected boundaries (vs. original spec)

The original spec had three concrete bugs that would have caused either false failures or unsafe file overwrites. This packet ships the corrected contract:

1. **Default manual evidence path is TODAY, not 20260629.** The historical
   `.ai/MANUAL_PUBLISH_EVIDENCE_20260629.md` is no longer the default
   read target. The default is `.ai/MANUAL_PUBLISH_EVIDENCE_<REVENUE_RUN_DATE>.md`,
   still overridable via `MANUAL_PUBLISH_EVIDENCE=…`. If today's file
   does not exist, the script creates an empty 3-block YAML template so
   the human operator can paste URLs into it later. The gate still reports
   No-Go (business, not script failure).

2. **`AUTOPILOT_STATUS.json` is safe-merged, not overwritten.** The
   orchestrator reads the existing file, parses it, and only updates the
   `revenue_self_run_v1` key while preserving every other top-level key
   verbatim. If the existing file is unreadable / not valid JSON, the
   script does NOT write to it and instead emits
   `.ai/AUTOPILOT_STATUS_WRITE_SKIPPED_<DATE>.md` with the parse error
   and human instructions. (Verified post-run: original 18 keys still
   present; new `revenue_self_run_v1` is the 19th.)

3. **Business No-Go is NOT a script failure.** All four scripts exit 0
   even when the gate decision is `no_go` or `conditional_go`. Only fatal
   parse failures / I/O errors trigger exit code 2. This keeps CI / audit
   signals honest: exit 0 + decision=no_go is a clean orchestrator run,
   not a broken script.

## Score-row bug fixed during dev

The first run of `self-run-select-posts.mjs` selected 0 posts because
`scoreRow` used `text.includes("published")` to detect already-published
rows. This substring also matched `status="pending_manual_review"` and
`publish_status="not_published"`, falsely flagging every seed row as
already-published and excluding it with `-100`. Fixed by switching to
whole-field equality on `status` and `publish_status`. Verified after
fix: 3 posts selected, gate Go.
