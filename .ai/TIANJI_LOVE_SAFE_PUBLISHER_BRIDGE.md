# TianJi Love Safe Publisher Bridge

> Status: **Phase 1 — credential-free, manual-review only**.
> Generated by `tianji-github-safe-publisher-bridge` on 2026-06-24.
> Audience: any future automation runner (n8n / Postiz / Mixpost) and the human operator who reviews the queue before anything is allowed near a real social account.

## 1. What this bridge is

The Safe Publisher Bridge is a **handoff file** for any future social-automation tool (n8n, Postiz, Mixpost, or anything else the operator later approves). It contains:

- Content metadata (titles, hooks, captions, body or script)
- Platform hints (which platform the slot is shaped for)
- Planned publish dates and windows
- A `manual_review_required: true` flag on **every** item
- A source pointer back to the originating daily publishing pack

It does **not** contain, store, or imply:

- Access tokens, API keys, client IDs, client secrets
- Cookies, sessions, bearer tokens, passwords, usernames
- Any platform account identifier
- Any mechanism that would let a process log in or post

In short: the bridge is a **queue**, not an executor. It tells a future tool *what* to post, *when*, and *where* — but the post itself is a No-Go for this skill and the runner that consumes this bridge must also be credential-free in phase 1.

The aggregate files at the top of `assets/marketing/` are the bridge output the skill is named for. The per-day files are the day-by-day sources the aggregate is built from.

## 3. Bridge contract

Each item in `publishing-queue.json` has this shape:

```text
queue_id                # stable id: <day-pack>::<content_id>
source_pack             # path to the daily pack this came from
source_queue            # path to the per-day queue json
publish_date            # planned date (ISO yyyy-mm-dd)
publish_window          # morning / noon / afternoon / evening / late_evening
channel                 # internal channel name (tiktok, instagram_reels, ...)
platform_hint           # friendly platform label (tiktok, instagram, youtube, email, website, ...)
content_id              # unique id within the day
content_type            # short_video / carousel / trust_post / seo_outline / ...
title                   # internal title
hook                    # first-line hook
caption                 # ready-to-paste caption
body_or_script          # full body or script
hashtags                # array of hashtags
cta_url                 # call-to-action destination
asset_note              # risk / safety note for the human reviewer
manual_review_required  # ALWAYS true in phase 1
review_status           # pending_manual_review (set by human)
publish_status          # not_published (set by human)
published_url           # left null until human posts
metrics_placeholder     # zero placeholders, no inference
notes                   # human-facing notes
```

Credential-related fields are **intentionally absent**, not blank. The bridge explicitly documents which fields would be dangerous so a future reader cannot accidentally fill them in.

If the grep returns anything other than `no credential shapes found`, the bridge is unsafe and must be regenerated before any consumer is allowed to read it.

## 5. How to stop / undo the bridge

The bridge is a static export. To make it inert:

```bash
# 1. Move it out of the marketing path so no consumer can find it
mkdir -p .ai/quarantine
mv assets/marketing/publishing-queue.json .ai/quarantine/
mv assets/marketing/publishing-queue.csv .ai/quarantine/

# 2. (Optional) leave the per-day queues in place; they are also inert until acted on

# 3. Record the move in .ai/CHANGELOG_AI.md
```

There is no running service to stop, no background job to kill, no scheduled task to disable. The bridge is pure data.

## 6. Allowed actions under this skill

- Export a publishing queue as JSON or CSV.
- Create `assets/marketing/publishing-queue.json` and `assets/marketing/publishing-queue.csv`.
- Create this document and update `.ai/CHANGELOG_AI.md` and `.ai/REVIEW_PACKET.md`.
- Run `git diff --check` and a targeted secret-shape scan over the changed files.

## 7. Forbidden actions under this skill

- Posting to any social platform, in any form (live API, scraped, browser-automation, scheduler).
- Using login cookies, tokens, app secrets, account credentials, or browser-login automation.
- Bypassing captcha, 2FA, platform limits, or account risk controls.
- Storing credentials in the repo or any generated file. Even a blank `""` placeholder for a credential-shaped field is discouraged — the field should not be present.
- Running Stripe checkout, paid smoke, production deploy, server mutation, provider live calls, or any operation that touches revenue.
- Reading, printing, copying, diffing, or inferring `.env` files, secrets, tokens, or production configuration.

## 8. How a future platform-safe adapter would be enabled

A future adapter (e.g. an n8n workflow, a Postiz connector, a Mixpost worker) is **not enabled by this skill**. To enable one, a human must:

1. Approve the adapter's data flow in a separate, named, auditable change.
2. Provide credentials **outside the repo** (e.g. via a platform-native secret store).
3. Keep the bridge file credential-free and only the adapter allowed to read the platform secret.
4. Mark `manual_review_required: true` on items that have not been human-reviewed, and only set it to `false` per item with a human-entered reason.
5. Record the change in `.ai/CHANGELOG_AI.md` and `.ai/REVIEW_PACKET.md` with the explicit gate status.

Until all five steps are completed for a specific adapter, the bridge remains in phase 1 (credential-free, manual review, no auto-posting).
